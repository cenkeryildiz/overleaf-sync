Open the corresponding source document if the shared editor initially shows a different file. Public caches contain only digest-pinned UI/compiler resources; private files/PDFs remain in IndexedDB.

## Automatic durable checkpoints (candidate)

Connected editing keeps the existing live collaboration behavior. Every accepted local edit first receives its synchronous browser recovery copy. Changed documents are then checked in bounded batches after an idle interval; closing the tab or using a sign-out link also requests a checkpoint when possible. Only document IDs and content hashes are sent for this verification; it does not publish client text or overwrite another collaborator's work.

The server rechecks the live session and write permission, flushes native persistence/history, and verifies the exact text against an immutable native history revision. A matching receipt permits removal of only that session's unchanged temporary recovery records. These native revisions are recoverable same-server history, not an off-host backup; use the existing encrypted instance-backup procedure for independent recovery.

A closing browser cannot reliably finish a network exchange. Pending key-only ownership markers therefore survive close: the next authenticated visit retries verification before cleanup. Unconfirmed or newer text, another active tab's copies, offline-only files/projects and unapplied recovery drafts remain recoverable. Missing Web Locks support retains pending copies rather than reclaiming them unsafely.

Reusable public compiler resources and saved offline project data are retained to avoid unnecessary downloads and data loss. Offline UI runtime upgrades use the browser's ordinary service-worker lifecycle, allowing existing offline editing windows to finish before obsolete UI caches are recycled. There is no blanket `localStorage`, IndexedDB or CacheStorage purge on logout or tab close. Clearing the browser profile or losing both the device and server can still lose data that has no independent backup.
