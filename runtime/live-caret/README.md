# Live insertion carets

CE+ already broadcasts each collaborator's text insertion position and draws a colored vertical caret with an identity tooltip. This change removes the native resettable 500-ms presence wait. A ref stores the latest position without rerendering React on every caret move; peer-join/document-change publication reads that ref. The typing producer coalesces the latest state into a zero-delay task queued after the transaction's text-flush timers, instead of waiting for the next display frame. Closing the editor cancels pending publication. Document transforms, authentication, permissions and compiler scheduling remain unchanged. A solo editor retains the existing five-minute idle interval until a peer joins. This does not promise zero network/rendering latency.

`frontend.patch` is the preferred change against CE+ ae07e781ab20dac2378420e5cf7a47f7d8bccbb5. `apply.mjs INPUT OUTPUT [MANIFEST_INPUT MANIFEST_OUTPUT]` applies the same changes to the pinned, already-installed timing-overlay bundle, refuses mismatched hashes/anchors and never overwrites its input. Preserve the previous bundle before installing the generated asset; reload editor tabs. The optional paired manifest paths produce content-digest query versions for IDE entrypoint URLs; install that manifest read-only at `/overleaf/services/web/public/manifest.json` and recreate the service once so ordinary refreshes fetch the changed asset instead of an older cached bundle. Keep the previous manifest for rollback. Restore that bundle to roll back. Source retains AGPL-3.0-only.

The focused test checks scheduling and refusal boundaries. `test/browser/live-cursors.browser.mjs` uses two synthetic identities, verifies both visible carets, peer movement, actual concurrent edits, the final peer position against source coordinates and reload convergence. The plan records exact measured timings and LAN limits. These checks do not establish instantaneous updates, WAN performance or cross-platform application acceptance.

The typing-specific check is `test/browser/caret-typing.browser.mjs`. It compares the retained previous bundle against the installed candidate on one disposable shared project, checks continuous typing/newlines/backspace, exact final caret/source/reload, and records frame-event to actual WebSocket send and peer DOM caret-position timings separately. These measurements exclude physical second-PC/network/display hardware latency; they are not a zero-lag guarantee.

`patchTypingCaret` is applied by the existing participant editor integration to the pinned recovery/LAN editor bundle. The main-bundle CLI above keeps its original contract. Install the generated editor with a content-versioned runtime/manifest, then refresh both tabs. For the browser check, `PREVIOUS_CARET_EDITOR` and `CANDIDATE_CARET_EDITOR` override only the disposable contexts; `PARTICIPANT_COMPILATION=1` checks the actual local-compute path. `CARET_TYPING_ROLE=owner` reverses typing direction. The test supports fresh fixture emails and a bounded two-profile deadline; it never needs the delivered demo's passwords.

The thin primary caret is the local insertion point. Colored flagged carets show other browser connections; their tooltips identify the participant. Another participant can keep an insertion point before text you add. A local one-character insertion check verifies model position, native DOM selection and the center of the two-pixel local caret stroke separately from the other participant marker; use CARET_LOCAL_INSPECT=1 (CARET_LOCAL_ONE_CHAR=1 for the minimal case) with the existing disposable-account harness.
