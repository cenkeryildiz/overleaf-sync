# Deferred central compilation — not the selected architecture

The user changed the first-version architecture to GitHub-hosted public resources and participant-provided compilation. This central service is archived implementation/evidence and is removed from the current Mac runtime. The existing CE+ DockerRunner implementation below was exercised before that correction: it executes each project/user job in a sibling container. The trusted CLSI service alone has the Docker socket; the web container does not. Job containers receive only their own `/compile` bind mount, no network, no capabilities, no new privileges, a read-only root, private temporary storage, and explicit memory/CPU/process limits. The existing native TeX/packages/fonts remain unchanged.

The worker shares the web container's existing network namespace for internal loopback history/resource URLs, but has separate filesystem/PID namespaces. The bundled CLSI is disabled with a runit `down` file. The worker listens on the original loopback port; no new host port is published. This is a privileged trusted component, not a service to expose to browsers or the internet.

The installed `async.queue` supplies bounded FIFO admission: four active jobs, at most 36 admitted jobs and two outstanding per project/user owner, a 60-second admission deadline. All five existing acquire callers await admission. Active jobs retain their native project locks until they finish; expiry does not let a second compiler write the same project concurrently. Worker startup removes only containers bearing its exact installation-owner label before accepting new requests, preventing stale orphan jobs from being reused after restart.

`job.Dockerfile` reuses pinned native image fc824f074798c705225d539a7cebc4dd4c3dd3de92bbb5e01010e266cca7fd81. It clears the application entrypoint and exposes the already-used native compiler wrappers through the normal tool paths. It does not install another TeX engine. `groups.json` records explicit Docker HostConfig limits; do not rely on the upstream runner's misleading top-level Memory value. The current mounted configuration and exact rollback live in the authoritative project plan. Socket group IDs, host directories and installation labels must be resolved for each host.
